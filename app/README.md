# 피트스톱 Android 앱

Pleos Connect에서 주행 기록과 현대차 취급설명서 주기를 바탕으로 정비 시점을 계산하고, 집이나 회사 근처에 들를 수 있는 시간대를 제안한다. 일반 정비소 후보를 확정하면 앱에 계획을 저장한다. 실제 접수는 전화나 마이현대에서 마친다.

## 실행

JDK 17, Android SDK Platform 35, 플랫폼 도구(adb), Pleos Connect v2.1 에뮬레이터가 필요하다. Android Studio에서 이 폴더를 열거나 에뮬레이터를 부팅하고 이 폴더에서 실행한다.

```sh
./gradlew testDebugUnitTest assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell am start -n app.pitstop/.MainActivity
```

Gradle은 settings.gradle.kts에 등록된 Pleos Maven 저장소에서 Vehicle 2.3.2, NaviHelper 3.0.5, SpeechToText와 TextToSpeech 3.3.1를 받는다. 첫 빌드에는 저장소 접근이 필요하다. release 빌드는 공모전 설치 시연을 위해 Android 개발용 키로 서명한다.

## 시연 순서

1. 정차 상태에서 처음 열면 감지한 차종을 확인한다. 소모품별 마지막 정비 시점을 고른다. 짧은 주기 항목의 기록을 모르면 ‘기준 잡기 점검’이 뜬다.
2. **별도 시연 시작 → 시동 걸 때 제안**을 누른다. 월요일 출발 전의 투싼 1.6 터보를 재현한다. 교통 체증 때문에 5,000 km 주기를 적용했고 1,000 km가 남았다. 하루 40 km이므로 25일 뒤가 교체 예상일이다. 출근길 08:30의 일반 정비소 후보를 확인한다.
3. **음성 대화 켜기**를 선택하면 한국어로 제안한다. “다른 시간”, “예약해줘”, 되읽기 뒤 “예약 확정”, 저장 뒤 “취소”로 답한다. 음성은 차량 내에서 처리한다. 시연 모드에서는 글자로 답할 수도 있다. 버튼으로는 **다른 시간 → 예약하기 → 확정**을 누른다. 요약에 표시된 항목·정비소·시각을 확인한 뒤 8초 안에 확정한다. 10초 안에는 바로 되돌릴 수 있다. 이후에는 예약 계획 취소와 취소 확정을 누른다.
4. **처음부터 → 출퇴근 1주**를 누르면 9,700 km, **처음부터 → 시내 단거리 1주**를 누르면 5,000 km 또는 6개월이다. 소모품 목록에서 두 주기를 비교한다.
5. **시동 걸 때 제안 → 제휴 가정 켜기 → 오일 양 부족 신호**를 누른다. 오늘 18:10 후보를 확정하면 첫 경유지 추가를 요청한다. 활성 안내 경로와 내비 제공자의 응답이 필요하다. **영업 종료 뒤 도착 시연**을 누르면 다른 날로 옮길 수 있다.
6. **아이오닉 5 산길 주행 → 오일 양 부족 신호**를 누른다. 산길 점수 1.00과 감속기 오일 가혹 주기, 브레이크액 점검에 함께 맡길 타이어 위치 교환을 확인한다.
7. **내 정비 기록으로 돌아가기**로 시연을 끝낸다. 실제 기록과 시연 기록은 각각 저장한다.

## 구조와 검증 범위

| 파일 | 역할 |
|---|---|
| agent/Planner.kt, Schedule.kt | 19개 차종·엔진 규칙, 가혹도에 따른 주기, 예약 후보와 정비 계획 |
| agent/DrivingPattern.kt | 최근 30일간 조건별 지수 가중 평균, 주행 종료 판단, 브레이크를 새로 밟은 횟수 |
| agent/DemoData.kt | 정비소 5곳, 가상 주행과 제휴 가정 빈 시간 |
| vehicle/VehicleSource.kt | 누적·이번 주행 거리와 시간, 브레이크 페달, 오일·브레이크액 양, 동력계와 연식 |
| voice/PleosVoice.kt, VoiceCommand.kt | 온디바이스 한국어 낭독, 질문 후 최대 8초 음성 입력, 최종 인식 결과로 명령 처리 |
| StartupReminder.kt | 기기 부팅 시 사용자가 켜 둔 정차 정비 알림. 마지막 실제 기록으로 판단 |
| navi/NaviClient.kt | 즐겨찾기, 정체 거리·급경사 내리막·회전·카메라 콜백, 경로·경유지 요청 |
| MainActivity.kt, ui/AgentScreen.kt | 차량의 화면 조작 제한을 구독하고 처음 설정·제안·확정·취소 화면 표시 |
| AgentViewModel.kt, AgentStore.kt | 정비 기록·예약 계획 저장, 요약과 되돌리기 기한 관리 |

- 에뮬레이터에서 이번 주행 거리와 시간을 지원하지 않는다. 실제 SDK 입력으로 주행을 나누고 분당 브레이크 횟수를 계산하는 동작은 단위 테스트로만 확인했다.
- 브레이크 페달의 상태 콜백은 수신했다. 엔진오일·브레이크액 양 속성은 시험 이미지에서 지원하지 않아 부족 신호 버튼으로 시연한다.
- 일반 모드는 지자체 자료에서 영업 중이며 명칭에 ‘블루핸즈’가 들어가고 좌표가 있는 72곳을 사용한다. 업체명·주소·좌표·운영시간만 포함했다. 자료에 시간이 없으면 공개 예약 시간대를 적용하고 공식 채널에서 확인한다. 집·회사 즐겨찾기가 없거나 범위에 지점이 없으면 전화 접수를 안내한다. 전체 가맹점 목록과 실제 예약 가능 여부는 공식 채널에서 확인해야 한다. [전국자동차정비업체표준데이터](https://www.data.go.kr/data/15028204/standard.do)
- 별도 시연은 샘플 정비소 5곳, 가상 빈 시간, 직선거리로 추정한 우회 시간을 사용한다. 실제 예약 송수신과 부품·정비 이력 연동은 제휴가 필요하다.
- 앱 실행 중 시동 상태를 구독한다. 차량 설정에서 ‘부팅 후 정비 알림’과 Android 알림 권한을 켜면, 헤드 유닛이 부팅될 때 저장된 실제 기록을 검사해 주차 상태에 한해 알림을 표시한다. 차량이 대기 상태에서 재개될 때 꺼진 앱을 자동으로 여는 기능은 실차에서 확인되지 않았다.
- 차량 화면 제한이 적용되면 제안이나 입력 화면을 숨긴다. 앱이 전면에 있고 음성 대화를 켰을 때, 주행 중 급한 안내는 한 번으로 제한하고 방향지시등·회전·주의 구간·카메라 근접 시 미룬다. 실제 주행 신호와 경유지·도착 시간은 실차 검증이 남았다.
- 설정의 ‘정비·주행 기록 삭제’는 재확인 후 실제·시연 기록을 모두 지운다. 음성은 Pleos ON_DEVICE 모드에서 처리하며 LLM이나 예약 서버로 전송하지 않는다.
- 차종별 수치와 자료 출처는 [차종별 정비 주기](../docs/maintenance-schedules.md)에 있다.
